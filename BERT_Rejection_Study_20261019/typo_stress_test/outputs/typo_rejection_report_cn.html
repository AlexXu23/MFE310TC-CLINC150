正常请求拼错以后，系统还能正确服务吗？

固定 clean validation 95% 接受率策略下，马氏距离对正常请求的误拒率从 clean 的 4.76% 变为 light 的 23.18%、medium 的 39.91%。下面将分类本身变错与拒识造成的服务损失分开检查。

Light 下正常误拒率分别为距离 23.18%、Entropy 21.76%、MSP 20.90%；距离的正确且接受率为 70.60%，另有 9.59% 的正常输入属于分类头本可正确却被拒绝。其中 clean 原本正确且被接受、扰动后分类仍正确却新被拒绝的平均为 356.00 条（占全部IS的 7.91%），这是更直接的新增服务损失。 Medium 下正常误拒率分别为距离 39.91%、Entropy 37.21%、MSP 36.39%；距离的正确且接受率为 52.79%，另有 12.57% 的正常输入属于分类头本可正确却被拒绝。其中 clean 原本正确且被接受、扰动后分类仍正确却新被拒绝的平均为 500.67 条（占全部IS的 11.13%），这是更直接的新增服务损失。 这组95%策略结果必须保留，不能通过改挑max-F1运行点掩盖它。同时，各种分数的阈值位置不同，不能仅据这个运行点断言某种分数在所有阈值下都更差。 保留的max-F1策略中，Light 的距离/Entropy正常误拒率为 7.91% / 9.91%，但对应OOS recall也为 59.73% / 59.97%，应共同评价误拒和未知漏检的取舍。 保留的max-F1策略中，Medium 的距离/Entropy正常误拒率为 17.61% / 20.24%，但对应OOS recall也为 57.27% / 59.20%，应共同评价误拒和未知漏检的取舍。

本轮保留现有 BERT 权重、训练得到的类中心与协方差、所有 clean validation 阈值。 MSP、Entropy、Mahalanobis 在相同原始文本及同一套 light/medium 扰动上比较。 95% 接受率策略是本轮关注的运行点；原 clean 实验的唯一主终点仍为“max-OOS-F1 策略下，距离 − MSP 的 OOS F1”，没有重定义。

先区分分类错误与拒识误伤

闭集分类检查原分类头是否给出正确意图，即使请求最终被拒绝也照常评价。 拒识决定是否向用户提供该预测。正常文本拼错后仍继承原 IS 标签，因此被拒绝计为正常请求误拒； 其中“分类头本来正确但被拒绝”和“分类头已分错且被拒绝”分开呈现。拒绝错误分类可以阻止错误执行，但仍没有完成原正常请求，不能混同于正确服务。 只在被接受子集上的准确率提高，可能只是拒绝了更多困难请求，不能据此称鲁棒性提升。
